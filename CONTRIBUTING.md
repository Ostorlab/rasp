# Contributing

Thank you for helping. Every change goes through a pull request.

## Issues

Open an issue for a bug or a feature request, with the templates offered. Don't report a vulnerability or a way around a check in a public issue: [`SECURITY.md`](SECURITY.md) says how to reach us privately.

## Pull requests

- Keep each pull request to one change, with the tests that cover it.
- Run what CI runs before you push: the commands are in [`.github/workflows/`](.github/workflows/), and the READMEs say how to build and test each part.
- Describe the change in a sentence or two.
- A pull request is merged once CI passes and a maintainer has approved it.
